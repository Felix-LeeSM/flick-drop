# 2026-11-12 i18n 용어집 (초안)

## Goal

Flick 화면을 영어·한국어·일본어로 옮기기 전에 용어 하나당 번역어 하나를 정한다.
이 문서는 다른 검토자(사람이나 다른 AI)에게 그대로 넘겨도 읽히도록 썼다.

### 검토자에게 부탁하는 일

1. 아래 용어표의 한국어·일본어 후보 중 하나를 고르거나 더 나은 말을 제안해 주세요. 각 칸의 첫 후보가 초안 작성자의 추천이에요.
2. 「열린 질문」 절의 질문마다 의견과 이유를 주세요.
3. 한국어 화면에 실제로 놓였을 때 어색한 말, 번역투, 일반 사용자가 모를 말을 짚어 주세요.
4. 일본어는 일본 웹 서비스 화면에서 흔히 쓰는 표현인지 봐 주세요.

## 제품 배경

Flick은 비밀번호·파일 같은 민감한 내용을 한 번만 열리는 링크로 전하는 셀프호스트 웹 서비스예요. 계정이 없어요.

- **링크로 보내기:** 브라우저가 내용을 암호화해 서버에 올리고 링크를 만들어요. 복호화 열쇠는 링크의 `#` 뒤에 있어서 서버로 전송되지 않아요. 받는 사람이 처음 여는 순간 서버에서 지워지고(burn), 아무도 안 열면 정한 시간(5분~7일)이 지나 지워져요.
- **코드로 보내기:** 두 기기가 동시에 켜져 있을 때 6자리 코드로 연결해 실시간으로 옮겨요. 서버는 메모리로만 중계하고 저장하지 않아요. 선택 사항으로 3자리 확인 번호를 맞춰 볼 수 있어요.
- **요청하기:** 내가 받아야 할 때 제출 링크를 만들어 상대에게 주고, 상대가 올린 내용을 내 수령 링크로 한 번 열어요.
- **패스프레이즈(passphrase):** 링크만으로는 열리지 않도록 덧붙이는 추가 문구예요. 로그인 정보 안의 「비밀번호(password)」 항목과 다른 개념이에요.
- 보낼 수 있는 종류: 텍스트, 파일, 로그인 정보, 카드, 신원 정보, 사용자 지정 항목.

## 문체 원칙 (초안)

| 구분 | 한국어 | 일본어 |
|---|---|---|
| 문장(설명·오류·안내) | 해요체 | です・ます |
| 버튼·탭 | 명사형 「링크 만들기」 | 「リンクを作成」 형 |
| 상태 표시 | 「만료됨」 같은 짧은 명사형 | 「期限切れ」 같은 명사형 |
| 숫자와 단위 | 붙여 씀 「10분」 | 「10分」 |
| 영문 대문자 장식(`micro` 라벨) | 대문자 변환 없이 그대로 | 그대로 |

- 같은 개념은 한 화면 안팎에서 같은 말로 쓴다.
- 사용자를 「당신」으로 부르지 않는다. 일본어도 「あなた」를 되도록 피한다.
- 번역하지 않는 말: `Flick`, `age`, `TOTP`, `CVC`, `URL`, `QR`, `HTTPS`, 코드·명령·경로.

## 먼저 정할 영어 원문 (제안)

지금 영어 화면도 같은 개념을 여러 말로 부른다(조사: `web/src` 전체). 번역하기 전에 영어 기준어를 하나로 정해야 번역도 하나가 된다.

| 개념 | 지금 섞여 쓰는 말 | 기준어 제안 |
|---|---|---|
| 보내는 내용 | secret, message, Text, delivery, content | **secret**(전체), **text**(종류 이름), delivery는 관리 화면의 「전달 건」으로만 |
| 받는 사람 | recipient(링크), receiver(코드) | **recipient** 하나로 |
| 사라짐 | burn, wiped, consumed, released, gone, removed, deleted, erased | **burn**(제품 문구), 기술 설명은 **delete** |
| 시간 | Expires after, Lifetime, expiry, deadline, TTL, timeout | 화면은 **Expires after / expired**, 문서는 **lifetime** |
| 열기 | open, retrieve, released, reveal, unlock | **open**, 패스프레이즈 입력 후는 **unlock** |
| 링크 | link, URL, share link, recipient link | **link**, 구분이 필요하면 recipient link / management link |
| 코드 모드 이름 | Send with code, live transfer, in-memory relay, live memory pipe, transfer session, code drop | 버튼은 **Send with code**, 설명은 **live transfer** |
| 잠금 조건 | incorrect access proofs, invalid passphrase attempts | **wrong passphrase attempts** |
| 열쇠 | decryption key, private key, request key | 사용자 문구는 **key** 하나 |
| 거절 | Deny(버튼), declined(오류) | **Decline** |

## Open Questions

1. **passphrase 한국어:** 「패스프레이즈」(외래어, 정확하지만 낯섦) / 「접근 문구」 / 「암호 문구」 중 무엇이 일반 사용자에게 바로 이해되나요? 「비밀번호」는 로그인 정보의 password 항목과 겹쳐서 제외했어요.
2. **burn 한국어:** 「소각」을 제품 정체성으로 쓸까요, 아니면 문장에서는 「사라져요」, 상태에서는 「삭제됨」처럼 평범하게 갈까요?
3. **secret 한국어·일본어:** 「비밀」 / 「시크릿」, 「シークレット」 / 「秘密情報」 중 무엇이 자연스러운가요? 「비밀 만들기」가 어색하면 「보낼 내용」 같은 우회도 가능해요.
4. **한국어 문체:** 해요체(친근)와 합니다체(공식) 중 무엇이 보안 도구에 맞나요?
5. **일본어 Expires after:** 카드 「有効期限」과 겹치지 않게 「有効時間」 / 「保存期間」 중 어느 쪽이 자연스러운가요?
6. **key:** 사용자 문구에서 「열쇠」와 「키」 중 무엇이 자연스러운가요?

## Decisions

- 2026-11-12 이전 결정: 언어는 ko·en·ja, 브라우저 언어 자동 감지 + 수동 전환, URL은 언어별로 바꾸지 않음, 로그인 정보의 라벨은 필드 ID로 저장하고 표시할 때 번역.
- 이 용어집 확정 전까지 시안(`web/src/routes/prototype/i18n-docs`)의 문구는 임시예요.
- 2026-11-19 결정(사용자) 및 후속 확정:
  - **전면 현지화 및 방식 대칭 제목 확정**: 페이지 제목(`링크로 보내기` · `코드로 보내기` · `링크 열어보기` · `링크로 요청하기`, 일본어 `リンクで送る` · `コードで送る` · `リンクを開く` · `リンクでリクエスト`), 전달 방식 탭, 실행 버튼, 헤더 이동 링크(`보내기` · `코드 입력` / `送る` · `コード入力`)까지 모두 사용자 언어로 현지화한다.
  - passphrase는 한국어 **비밀번호**(로그인 서식의 password 칸과 같은 말이 되는 것을 감수), 일본어는 **パスワード**.
  - **용어는 사용자 입장에서 정한다**(같은 날 사용자 지시): "추가 비밀번호"처럼 시스템 쪽 사정을 드러내는 말은 쓰지 않는다. 복호화→열다, 제출·접수→보내다·도착, 내용을 가리키는 "비밀"→내용, 제출 링크/비공개 받기 링크→상대에게 줄 링크/내 받기 링크, 업로드 예약→올릴 수 있는 시간, 전송 세션→전송, TOTP 시드→2단계 인증 설정 키, 신원 정보→개인 정보, 관리 화면의 "전달"→링크. HTTP 요청은 "요청"이라 부르지 않는다(기능 이름과 겹침).
  - 글꼴은 **Pretendard / Pretendard JP**, 제목은 Noto Serif KR·JP(`ko`/`ja` `.page-title`은 `line-height: 1.22`, `.micro`는 `0.75rem`).
  - 언어 전환은 **헤더 우측 `ThemeToggle` 옆 지구본 아이콘 메뉴**(`LanguageRow.svelte` in `SiteHeader.svelte`).
  - 로그인 정보 라벨: 저장 형식은 그대로 두고(영어 label 저장), 표시할 때 템플릿 필드 ID가 맞으면 보는 사람 언어로 바꾼다.
